## 추가 연습 테스트케이스 50개씩

원본 입력과 중복되지 않는 새 입력을 각 문제에 **50개씩** 추가했다. 코드에서 복원한 규칙으로 생성하고 별도 방식의 참조 구현으로 답을 계산했다. 공식 히든 테스트나 원문 최대 제한을 확보한 것은 아니다.

| 문제 | 기존 제공 입력 | 새 입력 | 포함한 경계·고부하 조건 | 새 입력·정답·검증 |
|---|---:|---:|---|---|
| 충전소 | 5 | 50 | 모서리, 거리 경계, 집 위 설치 금지, 1개 우선, 2개 필요, 불가능, N=10에서 늦게 탈락하는 배치 | [입력](1_charging_stations/generated_input.txt) · [출력](1_charging_stations/generated_output.txt) · [상세](1_charging_stations/generated_cases.json) |
| 농지 | 10 | 50 | 고립, 분기, 후진, 재파종, 수확 직전/당일, N=9·M=50·농지 최대 49칸 | [입력](2_farming/generated_input.txt) · [출력](2_farming/generated_output.txt) · [상세](2_farming/generated_cases.json) |

새 입력은 각각 **T=50인 한 묶음**이다. 아카이브의 히든 1개는 이 묶음을 뜻한다. 히든을 포함하면 기존 예제까지 실제 1번 55개, 2번 60개를 실행한다. 각 묶음의 50개를 시험 입력처럼 한 번의 PyPy 실행 안에서 순서대로 처리한다.

1번의 새 50개는 독립 분할 참조 구현·원본 풀이 2개·복원 풀이가 모두 일치했다. 사용자가 저장한 코드도 기존 5개, 새 50개와 단일 충전소가 가능한 추가 무작위 2,000개에서 일치했다. 2번은 새 입력의 **4,576개 시작 위치·방향**에서 독립 카운트다운 구현·원본·복원 풀이가 모두 일치했다.

생성 및 검증은 Python 3으로 실행하며, 시간 측정에는 PATH의 `pypy3`가 필요하다. 고정 시드는 1번 `2026091501`, 2번 `2026091502`이다.

```bash
python restored/ssafy_a_2026-09-15/1_charging_stations/generate_cases.py
python restored/ssafy_a_2026-09-15/2_farming/generate_cases.py
```

[아카이브 PyPy 서버 검증 기록](generated_cloud_verification.json)에는 실행 환경과 시간, 채점 결과를 별도로 보관한다. `individual_process_probe`는 묶음 등록 전 초기화 비용을 확인한 기록이며 현재 채점 입력 구성이 아니다.

### 1번 제출 코드의 PyPy3 실행 시간

| 실행 환경 | 새로 만든 서로 다른 50개 | 고부하 10개를 다섯 번 반복한 별도 50개 |
|---|---:|---:|
| 로컬 PyPy 7.3.4 | 2.018초 | 2.5948초 |
| 실제 아카이브 서버 PyPy 7.3.9 | 13.624초 | 19.275초 |

두 환경에서 출력은 모두 일치했지만 **서버의 고부하 50개는 15초를 넘었다.** 따라서 시험에서도 15초 안에 안정적으로 끝난다고 확정할 수 없다. 원문의 최대 N과 채점기 성능은 미확인이다.

현재 아카이브의 기존 VM 시간 여유 설정은 1.5배다. 기본 제한 15초에 이를 적용한 허용 22.5초로, 예제까지 포함한 실제 1번 55개는 16.516초, 2번 60개는 0.907초에 통과했다. 이 결과를 엄격한 15초 통과와 혼동하지 않는다. 시간 여유 설정과 제출 기록은 변경하지 않았다.

## 검증

Python 3.13.3, 고정 난수 시드 `20260915`로 실행했다. [상세 결과와 첫 농지 예제의 하루별 기록](verification.json)을 보관했다.

| 검증 | 결과 |
|---|---|
| 충전소 제공 입력 5개 | 원본 2개·복원 풀이·독립 참조 구현 전부 일치 |
| 농지 제공 입력 10개 | 원본·복원 풀이·독립 참조 구현 전부 일치 |
| 충전소 무작위 입력 | 실제 -15~15 설치 영역에서 2,000개 일치 |
| 충전소 원본 풀이 대조 | 무작위 80개, 제공 5개, 경계 7개에서 원본 두 개와 일치 |
| 충전소 경계 | 설치 개수 우선, 집 좌표 금지, 허용 거리 경계, 모서리, 불가능 등 7개 |
| 농지 무작위 입력 | 2,000개에서 최대 수확량 일치 |
| 농지 시작 상태별 대조 | 40,044개 시작 위치·방향에서 원본·복원·독립 구현 일치 |
| 농지 작은 지도 전수 대조 | 2×2 지도 16종 × 날짜 10종 = 160개 일치 |
| 관찰한 최대 크기의 별도 입력 | 충전소 N=10·농지 N=9·M=50에서 독립 구현과 일치. 실행 시간은 verification.json에 기록 |
| 50개 묶음 실행 | 제공 입력을 반복해 문제별 50개로 구성. 원본·복원 풀이의 출력 일치 및 합산 실행 시간을 verification.json에 기록 |
| 원본 보존 | 7개 파일 SHA-256 일치 |

실행 시간은 이 PC에서의 측정값이다. 50개 묶음 측정은 제공 입력을 반복한 것이며 새로운 공식 테스트케이스가 아니다. 공식 N·M 등의 최대 제한은 확인되지 않았으므로 공식 최악 입력 통과를 뜻하지 않는다.

### 독립 구현의 차이

- **충전소:** 제공 코드는 충전소 위치 한 개/두 개를 열거한다. 검증기는 집을 두 그룹으로 나누는 모든 경우를 고려하고, 각 그룹을 담당하는 충전소의 최솟값을 구해 비교한다. 한 개로 가능하면 그 값을 먼저 반환한다.
- **농지:** 제공 코드는 수확 가능한 절대 날짜와 방향 번호를 쓴다. 검증기는 각 농지의 남은 성장 일수를 매일 줄이고, 방향 벡터를 직접 회전시켜 같은 작업을 독립적으로 모사한다.

예제 출력은 아래와 같다.

```text
1번: 2, 3, 36, -1, 21
2번: 4, 0, 10, 11, 16, 14, 20, 18, 15, 22
```

저장소 루트에서 전체 검증을 재실행할 수 있다. Python 표준 라이브러리만 필요하다.

```bash
python restored/ssafy_a_2026-09-15/verify.py
```
