## 문제

N × N 크기의 정사각형 지형을 가진 행성이 있다. 각 칸은 농지 또는 산이며, 입력에서 0은 농지, 1은 산을 뜻한다. 처음에는 모든 농지가 비어 있다.

지구인들은 이 행성에 농사 로봇 **‘개척자’**를 보내 곡물을 수확하려고 한다. 로봇은 원하는 농지 한 칸에서 시작하며, 처음 바라보는 방향도 동·서·남·북 중 하나로 정할 수 있다. 로봇은 1일부터 M일까지 매일 **오전에는 현재 칸에서 작업하고, 오후에는 이동**한다.

시작 위치와 방향을 가장 잘 골랐을 때 M일 동안 수확할 수 있는 곡식의 최대 개수를 구하라. 시작 위치나 방향을 바꾸어 비교할 때마다 모든 농지는 처음의 빈 상태에서 다시 시작한다.

### 1. 씨앗, 싹, 곡식의 성장 과정

빈 농지에 씨를 심으면 **1일이 지난 다음 날 싹이 난다.** 그 농지에서 **k번째로 싹이 난 경우, 싹이 난 날로부터 3 + k일이 더 지나면 곡식이 열린다.** k는 1 이상의 정수이며, 농지마다 따로 센다.

- 처음 싹이 났다면, 싹이 난 날로부터 4일(3 + 1)이 더 지나 곡식이 열린다.
- 두 번째로 싹이 났다면, 싹이 난 날로부터 5일(3 + 2)이 더 지나 곡식이 열린다.
- 같은 농지에서 다시 농사를 지을수록 성장에 필요한 시간이 하루씩 길어진다. 수확해도 그 칸의 누적 재배 횟수는 초기화되지 않는다.

따라서 **p일에 k번째 씨를 심었다면 p + 1일에 싹이 나고, p + 1 + (3 + k) = p + 4 + k일의 오전부터 곡식이 열린 상태**가 된다. 다른 칸에 씨를 심은 횟수는 이 계산에 영향을 주지 않는다.

예를 들어 한 농지에 1일 오전 처음 씨를 심으면 2일에 싹이 나고 6일 오전부터 곡식이 열린다. 2~5일에는 아직 성장 중이므로 그 칸에 들어갈 수 없다. 곡식이 열려도 자동으로 수확되지는 않는다. 로봇이 그 칸에 서서 오전 작업을 해야 수확된다.

### 2. 오전 작업

로봇은 오전에 **현재 서 있는 농지의 상태에 따라 아래 작업 중 하나만** 수행한다.

- **빈 농지이고 오후에 이동할 곳이 있는 경우:** 현재 칸에 씨를 심는다.
- **빈 농지이고 오후에 이동할 곳이 없는 경우:** 씨를 심지 않고 아무 작업도 하지 않는다.
- **곡식이 열린 농지인 경우:** 곡식 1개를 수확한다. 수확한 칸은 빈 농지가 되며, 이동할 곳이 없어도 수확한다.

수확과 파종은 서로 다른 작업이다. 따라서 수확한 날 같은 칸에 바로 씨를 다시 심지 않는다. 이동할 곳이 있는지는 아래 오후 이동 규칙으로 판단한다.

### 3. 오후 이동

로봇은 현재 바라보는 방향을 기준으로 인접한 네 칸을 **오른쪽 → 앞 → 왼쪽 → 뒤** 순서로 살펴본다. 그중 **가장 먼저 발견한 이동 가능한 칸**으로 한 칸 이동한다. 매일 이동 방향을 자유롭게 고르는 것은 아니다.

다음 조건을 모두 만족해야 이동할 수 있다.

- 지도 안에 있는 농지이다. 산이나 지도 바깥으로는 갈 수 없다.
- 빈 농지이거나, 그날 이미 곡식이 열린 농지이다.

씨를 심은 뒤 아직 곡식이 열리지 않은 농지에는 들어갈 수 없다. 특히 싹이 자라는 농지는 지나갈 수 없다.

예를 들어 동쪽을 바라보고 있다면 **남쪽 → 동쪽 → 북쪽 → 서쪽** 순서로 확인한다. 남쪽에 싹이 자라고 동쪽이 빈 농지라면 동쪽으로 이동한다. 남쪽에 이미 곡식이 열려 있다면, 동쪽이 비어 있어도 우선순위가 높은 남쪽으로 이동한다.

이동하면 로봇이 바라보는 방향도 이동한 방향으로 바뀐다. 네 칸 모두 이동할 수 없으면 현재 위치에 머물며 방향도 유지한다. 하루에 여러 칸을 이동하지 않으며, 도착한 칸의 작업은 **다음 날 오전**에 한다.

### 4. 하루 처리와 종료 시점

날짜가 바뀌어 성장 기간이 지난 농지는 그날부터 곡식이 열린 것으로 판단한다. 그 상태에서 이동할 곳이 있는지 확인하고, **현재 칸의 오전 작업 → 오후 한 칸 이동 또는 대기** 순서로 하루를 진행한다. 오전 작업은 현재 칸만 바꾸므로 이웃 칸의 이동 가능 여부와 우선순위는 바뀌지 않는다.

곡식이 열린 날 오후에 해당 칸으로 이동할 수 있지만, 수확은 다음 날 오전에 한다. 앞의 예에서 6일 오후에 처음 그 칸에 도착했다면 실제 수확은 7일 오전이다.

M일의 오전에 수확한 곡식까지 정답에 포함한다. M일 오후에 곡식이 열린 칸에 도착하더라도, 다음 날의 작업은 없으므로 그 곡식은 정답에 포함되지 않는다.

## 입력

첫째 줄에 테스트케이스 수 T가 주어진다.

각 테스트케이스의 첫째 줄에 지도의 한 변의 길이 N과 작업하는 일수 M이 주어진다. 다음 N개의 줄에는 0 또는 1인 정수 N개가 공백으로 구분되어 주어진다.

```text
T
N M
a_1,1 ... a_1,N
...
a_N,1 ... a_N,N
```

## 출력

각 테스트케이스마다 `#테스트케이스번호 정답` 형식으로 출력한다. 번호는 1부터 시작한다. 정답은 시작 농지와 방향을 자유롭게 선택했을 때 M일 동안 수확할 수 있는 곡식의 최대 개수이다.

## 복원 근거와 제한

| 항목 | 확인한 내용 |
|---|---|
| 지도 값 | `1`은 산, 제공 입력의 `0`은 빈 농지 |
| 시작 상태 | 모든 농지 × 네 방향을 독립적으로 검사한 최댓값 |
| 이동 우선순위 | 원본의 네 방향 표를 해석하면 오른쪽, 앞, 왼쪽, 뒤 |
| 하루 처리 순서 | 이동 가능 여부 확인 → 현재 칸 파종/수확 → 이동 |
| 로봇과 하루 작업 | 제공 이미지: 농사 로봇 ‘개척자’, 오전 작업 후 오후 이동 |
| 성장 과정 | 제공 이미지: 파종 후 1일 뒤 발아, k번째 발아 후 3 + k일 뒤 곡식이 열림 |
| 성장 시점 | 위 성장 과정의 합은 `파종일 + 4 + k`이며 제공 코드의 계산과 일치 |
| 재파종 | 수확 후에도 해당 농지의 누적 파종 횟수를 유지 |
| 제공 입력 | 10개, N은 6~9, M은 10~50, 모든 지도의 테두리는 산 |
| 시간 제한 | 응시자 기억에 따르면 PyPy3 기준 50개 테스트케이스 합산 약 15초 |
| 미확인 | 공식 제목, 이미지에 없는 나머지 원문과 그림, T·N·M의 전체 제한, 테두리가 항상 산인지, 정확한 공식 시간 및 다른 언어의 제한, 메모리 제한 |

제공 입력에서 관찰한 범위는 원문의 최대 제한을 뜻하지 않는다. 테두리가 산인 것은 입력에서 관찰한 사실이고, 복원 규칙은 코드와 같이 지도 경계도 검사한다. 2026-09-18에 제공된 `Pasted image 20260916160231.png`에서 성장 과정과 오전/오후 규칙을 확인했다. 이미지에 없는 시작 상태·방향 갱신·최대 수확량 조건은 기존 코드 기반 복원 내용을 유지했다. 이미지의 Fig. 1·2는 내용이 보이지 않아 새 그림을 원본으로 제시하지 않는다.

## 추가 연습 입력 50개

제공 입력 10개를 보존하고 **중복 없는 새 입력 50개**를 추가했다. [입력](generated_input.txt), [정답](generated_output.txt), [케이스별 의도·검증 결과](generated_cases.json), [생성기](generate_cases.py)를 함께 보관한다.

- 지형 경계 12개, 성장 날짜 경계 8개, 무작위 15개, 고부하 15개다.
- 고립된 농지, 직선·꺾인 통로, 분기, 고리, 후진, 반복 파종을 포함했다.
- 두 칸 통로는 M=11/12, 17/18, 23/24를 각각 검사하여 수확일 직전과 당일을 구분한다.
- 고부하 15개는 모두 N=9·M=50이며, 내부 49칸이 모두 농지인 지도도 포함한다.
- 새 입력은 T=50 한 묶음이며, 아카이브에서 히든 1개로 보인다. 기존 예제까지 포함하면 실제 60개다.

전체 4,576개 시작 위치·방향에서 독립 성장 카운트다운·원본 풀이·복원 풀이를 대조해 일치했다. 로컬 PyPy 7.3.4에서 새 50개를 한 번에 실행한 시간은 복원 풀이 0.1117초, 원본 0.1427초였다.

N=6~9, M=10~50과 산 테두리는 제공 입력에서 관찰한 조건을 따랐다. 공식 최대 제한과 테두리 보장 여부는 미확인이다.
