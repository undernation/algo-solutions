## 마지막 코드에서 남은 문제

- `UPDATE value1 value2`에서 값을 읽기만 하고 실제 교체를 하지 않는다.
- PRINT는 `parent[(r, c)]` 대신 `find((r, c))`로 최종 대표를 찾아야 한다. 병합이 누적되면 직계 부모는 대표와 다를 수 있다.
- UNMERGE에서 전체 구성원을 먼저 수집한 후 부모를 초기화하는 순서는 유지한다. 분리 도중 대표 탐색을 하면 그룹 일부를 놓칠 수 있다.
- 첫 코드의 `merge_value` 오타와 딕셔너리 함수 호출은 마지막 코드에서 수정되었지만, 위 두 문제는 남아 있다.

## AI 참고 코드

아래는 첨부 대화의 AI 수정 코드이며 본인 정답 풀이가 아니다. 검증을 통과해도 이번 상태를 품으로 바꾸지 않는다.

```python
parent = {}
value = {}

def find(pos):
    while parent[pos] != pos:
        parent[pos] = parent[parent[pos]]
        pos = parent[pos]

    return pos


def solution(commands):
    global parent, value

    parent = {}
    value = {}
    answer = []

    for i in range(1, 51):
        for j in range(1, 51):
            parent[(i, j)] = (i, j)
            value[(i, j)] = None

    for command in commands:
        command = command.split()

        if command[0] == "UPDATE":

            if len(command) == 4:
                r = int(command[1])
                c = int(command[2])
                cur_value = command[3]

                root = find((r, c))
                value[root] = cur_value

            elif len(command) == 3:
                value1 = command[1]
                value2 = command[2]

                for pos in parent:
                    if parent[pos] != pos:
                        continue

                    if value[pos] == value1:
                        value[pos] = value2

        elif command[0] == "MERGE":
            r1 = int(command[1])
            c1 = int(command[2])
            r2 = int(command[3])
            c2 = int(command[4])

            root1 = find((r1, c1))
            root2 = find((r2, c2))

            # 이미 같은 그룹
            if root1 == root2:
                continue

            value1 = value[root1]
            value2 = value[root2]

            merged_value = value1 if value1 is not None else value2

            parent[root2] = root1

            value[root1] = merged_value
            value[root2] = None

        elif command[0] == "UNMERGE":
            r = int(command[1])
            c = int(command[2])

            target = (r, c)
            root = find(target)

            saved_value = value[root]

            members = []

            for pos in parent:
                if find(pos) == root:
                    members.append(pos)

            for pos in members:
                parent[pos] = pos
                value[pos] = None

            value[target] = saved_value

        else:
            r = int(command[1])
            c = int(command[2])

            root = find((r, c))

            if value[root] is None:
                answer.append("EMPTY")
            else:
                answer.append(value[root])

    return answer
```

## 검증 결과

[공식 문제](https://school.programmers.co.kr/learn/courses/30/lessons/150366)의 예제 2개와 명령 제약을 확인했다.

### 원본 반례

- `bulk_update_missing`: 명령 `["UPDATE 1 1 a", "UPDATE a b", "PRINT 1 1"]`, 원본 `['a']`, 정답 `['b']`.
- `immediate_parent_is_not_root`: 명령 `["UPDATE 1 1 a", "MERGE 1 1 1 2", "MERGE 1 3 1 1", "PRINT 1 2"]`, 원본 `['EMPTY']`, 정답 `['a']`.

### AI 참고 코드 검증

- Union-Find를 사용하지 않는 명시적 그룹 집합·셀별 값 구현과 비교했다.
- 공식 예제 2/2, 별도 경계 명령열 7개, 고정 시드 랜덤 명령열 2,000개에서 불일치 0건.
- 같은 랜덤 입력에서 마지막 본인 코드는 1,719개 명령열의 출력이 달랐다.
- 명령 1,000개인 깊은 병합 체인·반복 병합 해제·반복 전체 값 변경을 확인했다. 연속 함수 호출에서도 초기화 동작을 확인했다.
- 이 검증은 AI 참고 코드에 대한 로컬 검증이며, 자력 해결이나 공식 제출 통과로 기록하지 않는다.
